# 议场 AGORA 演示视频讲稿（5—8 分钟，1080p）

> 视频总时长目标 7 分钟。其中 5:00—7:10 为 AI 协同过程复现展示，累计超过官网要求的 2 分钟。所有画面必须来自真实运行和真实 Cursor 操作。

## 录制前检查

```text
[ ] Node.js 20.9+ 已安装
[ ] npm install 已完成
[ ] npm run dev 已启动
[ ] 浏览器窗口 1920×1080，缩放 100%
[ ] Cursor 已打开本项目
[ ] 终端字号调大，命令输出可读
[ ] 清空浏览器历史议题，回到初始页面
[ ] 关闭通知、聊天软件和无关标签
[ ] 录屏软件设置为 1080p、30fps 以上
```

## 0:00—0:40 痛点与定位

画面：浏览器首页 + 口头讲解。

讲稿：

> 这是议场 AGORA，一个面向高校大创和跨专业创新团队的多 Agent 协同工作流看板。
> 真实问题是：校园创新团队跨专业协作时，需求容易漂移，风险常常在后期才暴露，会议结束后也没有明确的负责人和验收指标。
> 本作品不是让 AI 替团队聊天或拍板，而是让五个职责边界清晰的 Agent 分别产出需求卡、工作流卡、风险卡、合规卡和行动决议卡。

## 0:40—1:30 创建议题与召集 Agent

画面：输入议题，展示五个 Agent 阵容。

操作：

1. 输入议题：`如何做校园节能试点？`
2. 输入背景：`宿舍用电数据需要脱敏，先验证告警准确率。`
3. 点击“召集议场”。

讲稿：

> 我输入一个真实议题：如何做校园节能试点。
> 背景约束是：宿舍用电数据需要脱敏，先验证告警准确率。
> 系统会召集五个职责不同的 Agent，每个角色只负责一类工作卡。

## 1:30—2:30 五个角色的结构化输出

画面：议事厅消息卡片和证据标签。

必须展示：

- 闻野：目标用户为宿舍学生与后勤管理者；
- 墨衡：一栋宿舍楼两周影子试点；
- 秋序：误报和学生负担的失败条件；
- 衡山：数据脱敏和人工确认边界。

讲稿：

> 可以看到，闻野先把议题还原成用户和场景问题；墨衡把它拆成可交付的工作流节点；秋序提出最需要验证的失败条件；衡山检查数据脱敏和人工确认边界。
> 每个观点都带证据类型和置信度，不是自由散文。

## 2:30—3:30 交叉质询与主持人约束

画面：点击“继续交叉质询”，再在输入框补充一条约束。

补充约束：

```text
无论如何，告警必须保留人工复核，不能自动通知学生。
```

讲稿：

> 我继续交叉质询，并补充一条人工约束：告警必须保留人工复核，不能自动通知学生。
> 系统会把这条主持人约束作为一条高置信度证据加入议事厅，而不是被忽略。

## 3:30—4:20 冲突图谱与冲突治理

画面：冲突图谱页。

讲稿：

> 冲突不是系统异常，而是正常工作流事件。图谱展示谁与谁在什么维度发生分歧。
> 范围冲突会被拆成节点，风险冲突会转成时间盒验证任务，责任和合规冲突会进入待人工确认门禁，但系统仍然继续生成可审查的决议草案。

## 4:20—5:00 决议书与导出

画面：决议书页，点击“导出决议书”，展示下载文件。

讲稿：

> 决议书包含建议行动、理由、下一步行动、负责人、验收指标和保留异议。
> 我点击导出，浏览器会下载一份 Markdown 决议书，可以继续转 PDF 或作为评审附件。

## 5:00—7:10 AI 协同过程复现展示（≥2 分钟）

画面：切换到 Cursor，真实回放至少一轮完整对话。

必须展示：

```text
5:00—5:20  说明三轮证据目录结构（prompts/screenshots/01—04）
5:20—6:00  展示“问题分析”Prompt，Cursor 回复根因
6:00—6:40  展示“方案实施”Prompt，Cursor 修改领域层并给出验证命令
6:40—7:10  展示“验收测试”Prompt 与 npm test 11 个用例通过、Git 提交记录
```

讲稿：

> 下面展示真实的 AI 协同过程。这是本轮的第 1 条对话：我发现不同议题得到固定话术，要求 Cursor 先分析、不立即改代码。
> 这是第 2 条对话：我要求它增加输入驱动的场景透镜，同时保持领域层纯函数和 Agent 职责边界。
> 这是第 3 条对话：我提出六条验收标准，要求补充自动化测试。这里可以看到类型检查通过、11 个测试用例通过，以及对应的 Git 提交。
> 相关截图和录屏已经归档在 prompts/screenshots/01—04 和 prompts/recordings/ 中。
